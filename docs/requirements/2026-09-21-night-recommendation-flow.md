# 夜间特殊访客与推荐书籍

**状态：已实现（2026-09-21）**

本轮实现：清场完成后总计约 6.5 秒安静 → 陈遥从门外侧边走近并轻敲三下 → 1.9m 内瞄准询问 → 实体馆藏检视与一次推荐 → 访客沿门外离场 → 推荐书重新入架且空手才完成。全程不开门；第一次询问允许手持已有书，提交仍必须在听过需求后单独点击。新增《夜空图鉴》于科普架原空槽，馆藏共 19 本、散落整理任务仍为 6 本。桌面和手机共用原输入；只读 DEV 显示后台判断，普通 UI 不显示答案。结果保留当前页面会话，不写入借还历史。实际参数见 README 和 docs/INTERACTION_FLOWS.md 第 12 节。

**对应项目：Nightfall Library / cute_lib**

## 0. Codex 执行要求

请直接在现有仓库 `WWweiweiHANK/cute_lib` 上实现，不要另建工程。

当前 `main` 已完成：借书、还书、跨交易记忆、闭馆阅读、起身与夜间自由行走、夜间整理、闭馆清场、桌面键鼠与手机横屏控制。

本需求必须接在：

```text
NIGHT_CLEARING_COMPLETE
```

之后。

本轮只实现：

> 普通读者全部离场 → 图书馆真正安静 → 门外出现一位正常的晚到访客 → 对方隔着已锁的入口询问想找的一类书 → 玩家回到馆内书架寻找并检视 → 拿一本书回到门口展示 / 推荐 → 访客根据推荐自然回应 → 记录推荐结果 → 访客离开。

暂时不要实现：

- 工资结算
- 房租
- 第二天
- 超自然访客
- AI 动态生成对话
- 多访客连续推荐
- 好感度
- 物品奖励
- 访客直接借走馆藏

# 1. 体验目标

前一阶段结束时：

```text
“馆里已经没人了。”
```

玩家以为普通工作已经结束。

保持一段真正的安静。

随后门外传来非常轻的敲门声。

不是 Jump Scare。

玩家走到门边，看见一位淋过一点雨、完全正常的年轻访客站在玻璃门外。

对方知道已经闭馆，因此不是来强行借书，而只是问：

> “不好意思，我知道已经关门了。我想明天来借一本书……你能不能先帮我推荐一本？”

这样既让夜间出现一个新人物，又不破坏“门已经锁了”和“借书必须核验证件”的规则。

# 3. 清场完成后的安静

“馆里已经没人了。”淡出之后：

继续保持约：


# 4. 访客到来

等待结束后：

门外出现一位访客。

不要突然 Spawn 到玻璃门正中央。

建议：

1. 访客从窗外 / 门外侧边缘沿遮雨区域走到入口。
2. 玩家如果正好看向入口，可以自然看见他走近。
3. 到门前以后停下。
4. 轻轻敲玻璃 / 门框三下。

音效：

```text
笃、笃、笃
```

音量克制。

禁止：

- 大门猛响
- 音乐 Stinger
- Camera Shake
- 自动把镜头强拉向门
- 灯闪

玩家可以自己转头去看。

# 5. 第一位夜间访客

暂定姓名：

**陈遥**

外观：

- 普通年轻成年人
- 深色防雨外套
- 头发稍微有一点被雨打湿
- 手上没有诡异物品
- 表情礼貌、略微不好意思
- 不进入图书馆

人物整体仍然低多边形，并与已有角色资产风格统一。

第一天不要把“特殊访客”做成恐怖角色。

这里的“特殊”仅指：

> 已闭馆后仍来到门口询问书籍。

# 8. 第一段对话

访客：

> “不好意思。”

停顿。

> “我知道已经关门了。”

再停顿。

> “我想明天来借一本书……能不能先请你帮我推荐一本？”

玩家不需要选择“愿意 / 不愿意”。

第一天直接继续工作即可。

玩家角色可以回应：

> “你想找什么样的？”

访客描述需求。

---

# 9. 第一日推荐需求

第一日使用一个明确、容易理解但需要真正找书的需求：

访客：

> “是给我妹妹看的。”

> “她最近总问我天上的星星为什么会亮。”

> “最好图多一点，别太难。”

把需求拆成三个自然条件：

1. 主题：星空 / 天文
2. 读者：儿童或入门读者
3. 特征：图多、难度低

不要把它显示为 checklist。

不要 UI 写：

```text
✓ Astronomy
✓ Child
✓ Illustrated
```

玩家只听自然语言。

# 12. 候选书不只一册

推荐玩法不能变成：

> 唯一一本文字发光的任务书。

玩家应该从真实书架中选择。

第一日可以让以下书都可正常拿取：

- 《夜空图鉴》——正确
- 《光与机械》——科普但主题不对
- 《林间观察》——自然、图多但不是天文
- 《远方的灯塔》——文学
- 《港口年代》——历史

不要给候选书加任务标记。

《夜空图鉴》应放在现有科普书架中的正常 ShelfSlot，而不是专门放到显眼台子上。

# 14. 访客等待状态

访客不要一直盯着玩家当前位置。

- 看向雨
- 偶尔看手机 / 门内
- 微微调整站姿

- 敲门催促
- 不断重复台词
- 突然消失
- 在玩家身后出现

玩家手上拿着任意一本馆藏。

走回入口。

靠近门内侧并看向访客。

准星变为可交互。

提示：

左键 / 手机使用：

```text

```

# 17. 推荐构图

进入轻量 DIALOGUE_FOCUS。

书仍然保留在玩家右侧前方。

画面应该同时看到：

- 门外访客
- 玩家手里的书封面 / 书脊
- 一部分玻璃门和雨夜

这与还书“顾客 + 手中书”构图可以共享部分逻辑。

不要把书自动转成完全标准角度；只做必要的小幅可读性调整。

---

# 18. 推荐是一次最终决定

为了让推荐具有意义：

**一次夜间访客只允许提交一本最终推荐。**

不要做：

```text
错了
→ 再拿一本
→ 一直试到对
```

否则它会变成穷举题。

玩家点击“推荐这本”以后：

该次推荐即提交。

---

# 19. 正确推荐

如果推荐：

《夜空图鉴》

访客看一下书。

停顿约 0.6 秒。

然后：

> “这个好像正合适。”

再停一下。

> “谢谢。那我明天再来借。”

注意：

**访客不把书带走。**

因为：

- 图书馆已经闭馆
- 没有核验读者证
- 推荐 ≠ 借出

书仍然属于馆藏，并最终回到玩家手上。

后台记录：

```js
isCorrect = true
```

但普通 UI 不出现：

- Correct
- +10
- 绿色勾
- 奖励金币

自然对白已经足够。

---

# 20. 错误推荐

如果推荐其他书：

访客看一下。

根据书大致类型，使用一条自然反馈。

通用版本：

> “嗯……好像不是我想找的那种。”

> “不过还是谢谢你。”

然后访客同样离开。

后台：

```js
isCorrect = false
```

不要显示：

- 错误
- 红叉
- 扣钱
- 正确答案

第一天也不要直接告诉玩家“应该是《夜空图鉴》”。

错误结果留给未来每日结算读取。

---

# 21. 如果多个书都合理

系统结构不能永远假定只有唯一正确答案。

未来 Request 必须支持：

```js
acceptableBookIds: [...]
```

或者基于 tag 计算多个可接受项。

如果两本书都真实满足所有描述：

两本都应该判为可接受。

不要做“猜设计师心中的唯一答案”。

第一日为了教学可以只放一个明显完全满足条件的候选。

---

# 22. 推荐之后书怎么处理

推荐提交以后：

访客没有拿走书。

书回到玩家右手。

当访客开始离开时，玩家恢复 FREE_LOOK。

玩家需要把这本书重新放回书架。

但不要重新启动完整 NIGHT_SHELVING 阶段。

规则：

- 当前仍为 NIGHT_RECOMMENDATION_COMPLETE_PENDING_RETURN
  或由 Controller 记录 pendingRecommendedBook。
- 玩家把手中的书放入任意 ShelfSlot 后，访客阶段才完全完成。
- 如果放错分类，仍然允许；后台继续由现有 shelving 数据记录最终布局。
- 不即时提示分类对错。

这样推荐流程继续服从已有“书从哪里拿，就需要由玩家负责放回”的物理规则。

---

# 23. 访客离开

推荐完成后：

访客：

- 点头
- 后退半步
- 转身
- 沿门外遮雨区域离开
- 逐渐走出玩家可见范围

他不需要进入门内。

不要瞬移消失。

访客离开时：

雨声保持正常。

不需要门铃，因为门没有打开。

---

# 24. 阶段完成

条件：

1. 推荐已经提交；
2. 访客已经离开；
3. 玩家手中没有推荐书；
4. 推荐书已经重新进入某个 ShelfSlot。

全部成立后：

```js
gamePhase = "NIGHT_RECOMMENDATION_COMPLETE";
```

可以短暂出现一句：

> 今晚的工作差不多结束了。

或者第一版完全不显示额外文本。

建议先采用更克制版本：

不额外提示，只让环境恢复安静。

下一轮日结系统再接管。

# 30. Cozy Horror 边界

这次仍然几乎没有恐怖。

真正的氛围点只是：

> 刚刚已经确认“馆里没人了”，结果门外又有人敲门。

但这个人是正常人。

不要：

- 黑眼睛
- 面无表情长时间盯人
- 不合理站姿
- 说奇怪的话
- 说知道玩家名字
- 问不存在的书
- 消失
- 出现在馆内

第一天只建立：

**闭馆以后也可能有人来问书。**

未来天数再逐渐异常。

# 32. UI

普通模式只需要：

# 33. 玩家忘记需求怎么办

第一版不要在 HUD 常驻显示需求。

但可以允许玩家空手回到门边再次点击访客。

访客用自然语言重复一遍简短需求：

> “就是给小孩子看的星空书，图多一点、别太难。”

这不是“查看任务日志”，而是重新问对方。

最多重复同一简短需求，不增加新信息。

---

# 34. 玩家持错误书回来前可以换

玩家可以：

- 拿书回来
- 看看访客
- 不提交
- 返回书架
- 把书放回
- 换另一本

真正提交发生在对访客执行“推荐这本”的那一刻。

## A. 时序

- NIGHT_CLEARING_COMPLETE 后不会立即 Spawn
- 等待窗口成立
- 访客从门外路径进入
- 敲门后可互动

## B. 对话

- 玩家超距不能询问
- 靠近可以询问
- DIALOGUE_FOCUS 参数平滑
- 对话后进入 NIGHT_RECOMMENDATION_SEARCH

## C. 正确推荐

- 找到《夜空图鉴》
- R 检视可用
- 返回门口
- 提交
- `isCorrect === true`
- 普通 UI 不显示“正确”

## D. 错误推荐

- 提交《林间观察》或其他错误书
- `isCorrect === false`
- 访客仍自然离开
- 普通 UI 无红叉 / 分数

## E. 一次提交

- 提交后不能换书重试
- 不允许重复写 recommendationResult

## F. 重复需求

- 空手回到访客处，在提交前可以再次询问需求
- 不改变正确答案

## G. 馆藏归属

- 访客不拿走推荐书
- 书返回玩家右手
- 必须重新放入 ShelfSlot
- 放错类别仍允许

## H. 完成条件

只有：

- 已提交
- 访客已离开
- 推荐书已重新入架
- 玩家空手

才进入 NIGHT_RECOMMENDATION_COMPLETE。
