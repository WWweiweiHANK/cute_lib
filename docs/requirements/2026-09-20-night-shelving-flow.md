# 夜间整理书籍：自由行走、拾取、检视与书架归位

**状态：设计需求 / 待实现**

**对应项目：Nightfall Library / cute_lib**

## 0. 给 Codex 的执行要求

请直接在现有仓库 `WWweiweiHANK/cute_lib` 上实现，不要另建工程，不要重做已经存在的借书、还书、书籍检视、对话镜头和 Cozy Horror 场景系统。

本需求依赖上一阶段的“闭馆阅读转场 → CLOSED → 起身 → NIGHT_FREE_ROAM”。如果当前分支尚未实现夜间自由行动，请先阅读：

`docs/requirements/2026-09-20-closing-reading-transition.md`

不要用瞬移、按钮跳转或单独测试房间绕过该依赖。完成夜间自由行动后，再接入本轮整理书籍玩法。

本轮只实现：

> 夜间自由行走 → 发现散落书籍 → 拾取 → 必要时 R 检视 → 判断类别 → 走到书架 → 点击具体位置放入 → 可再次拿出并重排 → 所有待整理书进入书架后结束整理阶段。

暂时不要实现：

- 驱赶逗留顾客
- 夜间神秘访客
- 推荐书籍
- 工资结算
- 房租
- 超自然事件
- 第二天
- 自动排序
- 立即正确 / 错误反馈

---

# 1. 核心设计目标

这一轮不是做“拖动物品到正确颜色框”的小游戏。

玩家应该感觉：

> 我下班前还要把读者留下的书收起来，走进书架之间，把它们一本一本放回去。

核心动作链：

```text
自由行走
↓
发现散落书
↓
左键拾取
↓
书进入右手
↓
必要时 R 检视
↓
旋转 / 翻页 / 看封面、书脊和内容
↓
判断它属于哪一类
↓
走到对应书架
↓
点击书架上的具体空位
↓
书滑入该位置
↓
继续寻找下一本
```

最重要的规则：

> **允许放错，而且不即时告诉玩家。**

---

# 2. Game Phase

在夜间阶段增加清晰的高层状态：

```js
NIGHT_FREE_ROAM
NIGHT_SHELVING
NIGHT_SHELVING_COMPLETE
```

进入 NIGHT_FREE_ROAM 后，如果当天存在待整理书籍，则立即进入：

```js
gamePhase = "NIGHT_SHELVING";
```

Camera Mode 与 Game Phase 继续分离：

```text
Game Phase: NIGHT_SHELVING
Camera Mode: FREE_LOOK
```

当玩家拿起书按 R：

```text
Game Phase: NIGHT_SHELVING
Camera Mode: OBJECT_INSPECT
```

不要把夜间整理塞进借书 / 还书 Transaction 状态机。

建议使用独立：

```js
NightShelvingController
```

---

# 3. 指定一个“可整理书架区”

不要把整个图书馆所有装饰书架都改造成重型交互物件。

本轮指定一组真正用于整理的书架：

```text
MAIN SORTING SHELVES
```

它位于玩家闭馆后可以自然走到的区域。

这组书架划分为四个明确区域：

1. 文学
2. 历史 / 人文
3. 自然
4. 科普

分类标识必须是世界内物件，例如：

- 木质小牌
- 印刷标签
- 书架端头标识

不要做成悬浮 HUD。

建议每个分类同时使用：

- 中文文字
- 一个简单小图标

颜色只能作为辅助，不能成为唯一判断依据。

---

# 4. 书架必须是真的“可操作空间”

玩家不是点击“文学按钮”完成归位。

每个分类书架应包含真实的：

```js
ShelfSlot
```

例如：

```js
{
  slotId,
  shelfId,
  category,
  localPosition,
  localRotation,
  occupantBookId
}
```

建议第一版：

- 4 个分类区
- 每类 6 个可放置槽位
- 共 24 个 Slot

每一格都具有真实 3D 位置。

玩家拿着书时，需要看向某个具体空位并左键放入。

不是拖拽。

---

# 5. 指定整理书架中的现有书也可交互

为了落实“整个书架都可以交互”的设计：

指定的 MAIN SORTING SHELVES 中，不要全部使用 InstancedMesh 装饰书。

建议初始每个分类区已有约 3 本实体书：

```text
4 个分类 × 3 本
≈ 12 本现有书
```

这些书：

- 都可以被玩家左键拿出来
- 可以 R 检视
- 可以放到其他空位
- 可以被错误地放到其他类别

也就是说：

> 玩家不是只能操作今晚地上的任务书，而是真的可以重新整理这一小组书架。

图书馆其他背景书架可以继续维持装饰性 InstancedMesh，避免性能浪费。

# 6. 第一版散落书籍数量

夜间第一轮准备：

**6 本散落书。**

不要随机生成位置。

使用固定、经过构图设计的位置，方便测试。

建议：

1. 阅读桌上 1 本
2. 阅读桌下地面 1 本
3. 椅子旁 1 本
4. 窗边地面 1 本
5. 书架过道边 1 本
6. 柜台外侧附近 1 本

玩家从柜台起身以后，应该自然地逐渐发现它们。

不要把六本书堆在一起。

允许准星在真正对准可交互书籍时略微变化。

# 9. 拾取散落书

NIGHT_SHELVING 使用夜间中心 Raycaster。

玩家看向书并左键：

```text
场景中的书
↓
右手持有
```

保持现有统一语言：

- 左键 = 拾取 / 使用
- R = 进入 / 退出书籍检视
- 滚轮 = 翻页
- 检视中左键拖动 = 旋转

一次只允许持有一本书。

如果手上已有书，再点击另一书：

不要自动交换。

可以不发生动作，或者给一个非常轻的中性提示：

```text
手上已经拿着一本书。
```

不要弹大 UI。

---

# 10. FREE_ROAM 下的手持表现

书进入右手后：

放在画面右下偏侧位置。

要求：

- 不遮挡中心视野
- 仍能读到部分封面 / 书脊
- 玩家可以继续自由行走
- 不影响中心 Raycaster 判断书架位置

走路时书可以有极轻微惯性，但不要大幅晃动。

---

# 11. 夜间书籍检视

继续复用现有 OBJECT_INSPECT。

从 FREE_LOOK 按 R：

```text
FREE_LOOK
↓
OBJECT_INSPECT
```

进入检视时：

- 玩家移动暂停
- 普通第一人称视角暂停
- 书移到中央
- 鼠标用于旋转书
- 滚轮翻页
- R 再次退出

不要新做另一套夜间检查 UI。

如果夜间 FREE_LOOK 使用 Pointer Lock，则 OBJECT_INSPECT 必须与现有输入兼容。

推荐：

- Pointer Lock 可以保持
- 检视时不更新相机 yaw / pitch
- 按住左键并移动鼠标时，将 movementX / movementY 用于旋转书籍
- R 退出后恢复 FREE_LOOK

尽量避免每检查一本书都要求玩家重新点击页面恢复控制。

---

# 12. 书架交互方式

玩家手中有书并靠近指定书架时：

中心 Raycaster 命中该书架的 Slot 区域。

空 Slot 可以出现非常轻的空间反馈：

- 准星稍微变化
- 可选：目标位置出现极淡的短线 / 缝隙提示

不要出现：

- 绿色正确框
- 红色错误框
- “放这里！”
- 箭头

左键：

```text
持有书
↓
点击目标空位
↓
书移动 / 滑入该 ShelfSlot
```

---

# 13. 放置动画

不要瞬移。

书从右手到 ShelfSlot：

约：

```text
0.25 ～ 0.45 秒
```

动作：

1. 朝槽位对齐
2. 稍微滑入
3. 最终与其他书脊齐平

播放非常轻的：

- 纸张摩擦
- 木架轻碰

不要播放成功音效。

---

# 14. 允许放错

这是本轮最重要的规则。

例如：

`《林间观察》`

正确类别是：

自然。

玩家却把它放到：

文学。

系统必须：

**正常放进去。**

不能：

- 拒绝
- 弹回手里
- 红字
- 错误音
- 自动换到正确书架
- 提示“分类错误”

后台只记录：

```js
finalShelfCategory = "literature";
actualCategory = "nature";
```

即时体验完全安静。

---

# 15. 已放入的书可以重新拿出来

玩家空手时，看向整理书架中的实体书并左键：

```text
ShelfSlot occupant
↓
右手持有
↓
slot 变为空
```

然后可以：

- R 检视
- 放回原位
- 放到其他位置

因此玩家如果中途意识到：

> “这本好像放错了。”

可以自己修正。

系统不要主动提醒。

---

# 16. 初始书架中的书也允许放错

不仅今晚散落的 6 本书可以移动。

MAIN SORTING SHELVES 中原本存在的约 12 本书也可以被拿出来重新放。

如果玩家把原本正确的一本书挪错：

后台同样记录最终位置。

但不要即时反馈。

这样才能真正实现：

> 整个整理书架是一个持续可操作的物理空间。

---

# 17. Occupied Slot 规则

玩家手上有书时点击已经被占用的 Slot：

不要把两本书重叠。

第一版不做复杂交换。

建议：

- 不执行放置
- 播放极轻的木头碰触
- 或给非常小的中性提示：“这里没有位置。”

这不是正确性反馈，只是物理空间反馈。

# 18. 分类数据

每本 BookInstance / BookDefinition 必须有：

```js
category
```

例如：

```js
"literature"
"history"
"nature"
"science"
```

书架区同样具有：

```js
shelf.category
```

最终结算只比较：

```js
book.category === finalShelf.category
```

不要在放置过程中调用这一比较来阻止玩家。

src/night-shelving.js

负责：

# 20. “任务完成”的定义

这一轮完成条件不是：

所有书都放对。

而是：

> **今晚指定的六本散落书已经全部进入某个书架槽位。**

也就是说：

哪怕全部放错，

整理工作在流程上仍然完成。

后台再计算：

```js
correctPlacementCount
wrongPlacementCount
```

但普通玩家当下看不到。

---

# 21. 完成后的反馈

最后一本散落书放进任意书架以后：

不要：

- 出现 PERFECT
- 显示 5/6
- 显示错误数量
- 播放胜利音乐

可以只出现一句非常轻的中性文本：

> 书都收起来了。

约 1～1.5 秒淡出。

然后：

```js
gamePhase = "NIGHT_SHELVING_COMPLETE";
```

为下一阶段“清场 / 检查馆内是否还有顾客”预留。

---

# 22. 如果玩家之后又把任务书拿出来

如果在 NIGHT_SHELVING_COMPLETE 后尚未进入下一阶段，玩家又把一本文书拿出来：

```js
isTaskComplete() === false
```

完成状态可以撤销。

不要让书悬在玩家手上却仍显示“已经全部收完”。

# 26. Cozy Horror 氛围

这一轮仍然不增加超自然内容。

情绪保持：

**80% Cozy / 15% Lonely / 5% Unease**

不安来自：

- 闭馆后只有玩家一个人在走动
- 书架之间的暗区
- 身后远处仍亮着的柜台台灯
- 雨声
- 自己的脚步

不要加入：

- 鬼影
- 自动掉书
- 突然脚步
- 灯闪
- 门开
- 小孩
- 书自己移动

# 27. 光线必须保证书可见

氛围不能伤害玩法。

所有散落书：

必须在合理距离上可辨认。

可以通过：

- 局部暖光
- 微弱边缘亮度
- 地面与封面对比

提高可见度。

不要用游戏式描边弥补过暗灯光。

# 29. 交互距离

建议：

```js

```

准星不进入可交互状态。

# 30. 放置位置判定

Raycaster 命中书架表面后：

转换到 shelf local coordinates。

选择点击位置附近最近的空 ShelfSlot。

要求：

- 点击上层，不要把书放到下层
- 点击左边，不要跳到最右边
- 放置结果要符合空间直觉

Slot 选择半径过大时不应自动吸附到远处空位。

---

# 31. 不做拖拽摆放

不要实现自由 3D 拖拽物理。

规则保持简单：

```text
手里有书
↓
看向槽位
↓
左键
↓
吸附放置
```

这样与现有交互语言一致。

# 35. 自动测试

新增：

```text
tests/night-shelving.mjs
```

至少覆盖：

## A. 拾取

- 走近地面书
- 左键拾取
- 书进入右手
- 原场景位置为空
- 一次只能持有一本

## B. 检视

- 持书按 R
- 进入 OBJECT_INSPECT
- 玩家无法移动
- 拖动旋转
- 滚轮翻页
- R 返回右手
- 回到 FREE_LOOK

## C. 正确放置

- 文学书放到文学 ShelfSlot
- 正常进入 Slot
- 不出现即时“正确”提示

## D. 错误放置

- 自然书放进文学书架
- 系统允许
- 不弹错
- 后台 `isCorrect === false`

## E. 重新整理

- 从书架拿回已放置书
- 原 Slot 释放
- 放到另一位置
- 最终记录只反映最终布局

## F. Occupied Slot

- 已占用位置不能叠两本书

## G. 完成条件

- 六本任务书全部进入任意 ShelfSlot
- `NIGHT_SHELVING_COMPLETE`
- 不要求全部正确

## H. 错误反馈延迟

- 完成时普通 UI 不显示正确数 / 错误数
