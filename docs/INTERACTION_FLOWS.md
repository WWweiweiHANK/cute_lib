# Nightfall Library 交互流程设计

> 本文记录 2026-09-18 已确认的交互方案。重点是统一玩家的操作语言，减少按键数量，并明确借书、还书、阅读过场与整理书架四类流程。

> 实现进度（2026-09-21）：借书、还书与三笔跨交易记忆测试已实现。赔偿/不追究仅处理选中损坏，回到持书后可继续检查，主动点击归还托盘才结束交易；此规则也适用于独立还书入口。闭馆阅读、行走与书架整理见第 10 节，闭馆清场见第 11 节；门外访客与一次书籍推荐已接入，见第 12 节。

## 1. 全局交互原则

### 1.1 核心操作语言

- **鼠标移动**：控制视线。
- **鼠标左键单击**：拾取物品 / 使用手中物品 / 点击可交互信息。
- **R**：进入或退出“书籍检视模式”。
- **检视模式中按住左键拖动**：旋转书籍，可从各角度查看。
- **鼠标滚轮**：翻页 / 合理范围内前后翻看。
- 尽量不引入额外功能键，不使用拖拽完成“拿起—放置”这类基础工作动作。

### 1.2 两种空间状态

#### 柜台工作状态
用于借书与还书。

- 玩家坐在柜台后。
- 不能自由行走。
- 鼠标只允许小幅转头，保持固定构图与夜班柜台氛围。
- 物品拾取后默认进入**右手持有位置**，而不是直接占满画面中央。

#### 整理书架状态
用于夜间/闭馆后的收书与归类。

- 玩家可以自由行走。
- 仍沿用相同的“点击拾取 → 右手持有 → R 检视 → 点击目标位置放置”的交互语言。

# 2. 书籍的统一状态

一本书在游戏中主要有以下状态：

1. **场景中**
2. **右手持有**
3. **中央检视**
4. **用于场景交互**
5. **被放置 / 被扫码 / 被退回**

## 2.1 拾取

玩家左键点击桌面、地面或书架上的书：

- 书从原位置离开。
- 移动到画面右侧的右手持有位置。
- 保持能看到封面 / 书脊的一部分，书脊应尽量能阅读标题。
- 此时玩家仍可正常看向顾客或环境。

## 2.2 进入检视

手中持书时按 **R**：

- 书从右侧移动到画面中央。
- 进入书籍检视模式。
- 玩家不再执行普通场景点击。

检视模式中：

- **按住左键拖动**：旋转书籍。
- **滚轮**：翻页。
- 可查看封面、封底、书脊、页面及预设的损坏位置。

再次按 **R**：

- 退出检视模式。
- 书回到右手持有位置。
- 玩家恢复对环境的普通交互。

# 3. 借书流程

## 3.1 顾客入场

顾客走到柜台前，将：

- 读者证
- 要借的书

放到桌面。

玩家保持固定柜台视角。

## 3.2 查看读者证

玩家左键点击读者证：

- 读者证被拾取。
- 直接显示在画面右侧、足够清晰可读的位置。
- **读者证不需要再按 R 才能查看。**
- 玩家可以一边看证件，一边移动视线观察顾客本人。

### 证件上的可交互信息

证件不需要被拆成大量区域，只保留少量关键热点，例如：

- 照片
- 姓名
- 日期 / 有效信息

这些热点是“提出疑问”的入口，不是小游戏式找茬。

### 对证件提出疑问

如果玩家认为某一项有问题：

1. 直接点击该信息区域。
2. 立即触发与该信息相关的提问 / 对话。
3. **不需要再点击顾客才能开始提问。**

例如：

- 点击照片 → 询问“这张照片和你现在看起来不太一样。”
- 点击日期 → 询问证件日期 / 有效性相关问题。

顾客回答后，玩家仍保留证件。

### 结束证件阶段

玩家持有证件时点击顾客：

弹出一个很轻的两项选择：

- **还给你**
- **我还有问题**

选择“还给你”：

- 证件递还顾客。
- 证件核验阶段结束。

选择“我还有问题”：

- 继续保留证件。
- 玩家可以继续点击证件信息提出问题。

这样避免“把证件放回桌面”这一不自然动作。

## 3.3 检查借阅书籍

玩家点击桌上的书：

- 拾取到右手位置。

如需仔细检查：

1. 按 **R** 进入检视。
2. 按住左键拖动旋转。
3. 滚轮翻页。
4. 再按 **R** 退出检视。

## 3.4 借出 / 拒借

书处于右手持有状态时：

### 借出

玩家点击右侧扫码机 / 借出设备：

- 手中的书移动到扫码区域。
- “滴”一声。
- 借出成功。

### 拒绝借出

玩家点击待处理书篮 / 拒借区：

- 书被放入待处理区域。
- 本次借阅不成立。

系统不替玩家自动判断证件是否正确；玩家的行为本身就是最终决定。

# 4. 还书流程

还书强调“检查书籍 → 指出损坏 → 与顾客交涉 → 决定赔偿或放过”。开始页选择还书测试，支持 `?mode=return&case=A/B`；A 为有封面划痕的《远方的灯塔》，B 为无损坏的《城市里的雨》。仅处理一笔交易。

## 4.1 顾客提交书籍

顾客来到柜台，说「你好，我来还书。」后只放书，不放借阅证。入场、手部动作、轻微对话聚焦沿用借书流程。

玩家点击书：

- 书进入右手持有状态。

按 **R**：

- 进入中央检视。

玩家可以：

- 旋转书籍。
- 翻页。
- 查看封面、书脊、页面。
- 观察划痕、污渍、页面撕裂 / 缺角。

## 4.2 破损如何实现

破损**不需要做复杂的 3D 建模**。

例如封面划痕可以由：

- 贴图 / decal / 局部纹理表现视觉效果。
- 实际封面 / 书页表面的 UV 区域负责点击检测；只有当前页、朝向玩家且未被遮挡的损坏可被点中。不新增热点几何，也不显示轮廓或文字标签。

因此“看得见的划痕”和“可点击区域”可以分离实现，不需要给每一道划痕增加实体几何。

### 点击与旋转冲突的处理

在检视模式中：

- **短按 / 轻点左键**：点击损坏热点。
- **按住并发生拖动**：旋转书籍。

短按不超过 250ms、移动不超过 6px，且按下和松开均在同一损坏上才提问。超过 6px，或长按超过 250ms 后移动，进入拖动；拖动松开不会提问。划痕、污渍和缺角均由 Canvas 纹理生成，责任字段不参与绘制。

## 4.3 点击损坏后的镜头与对话

当玩家点击一个确认存在的损坏热点，例如封面划痕：

1. 记录书的 rotation、quaternion 和当前页码，停止拖动惯性。
2. 书从中央检视位置移动到画面右侧。
3. **保持刚才检查时的姿态，不自动转正、合上或换页。** 极侧角度按选中表面的可见性收敛平移距离；展开书向右下稍远处移动，为脸部留空间。
4. 视线重新构图，使玩家能够同时看到：
   - 顾客
   - 有问题的书 / 破损位置
5. 自动进入该破损对应的对话。

例如：

“这里的封面为什么有一道划痕？”

镜头使用 DIALOGUE_FOCUS，在 0.7 秒内轻聚焦顾客，书仍在右下方。近处阅读补光随书移到右侧，保持损坏可见，不改变环境照明。污渍对应「这一页上的污渍是怎么回事？」；撕裂对应「这一页怎么破了？」。顾客回答「啊……这个。」停 0.5 秒，「可能是不小心碰到哪里了。」再停顿，「抱歉。」。

## 4.4 赔偿决策就在对话中完成

顾客解释之后，**不要退出对话再做额外操作**。

当前对话仅提供两项原生文字按钮：

- 要求赔偿
- 不追究

要求赔偿：玩家说「这属于借阅期间造成的损坏，需要赔偿。」，顾客说「好吧，我明白了。」，播放轻微纸张收据声。不追究：顾客说「谢谢。」。只记录这一处损坏的决定，书回到右手 BOOK_HELD；可再次 R 检查其他位置。重复质询同一处更新该处决定，不叠加记录。没有检查进度或未处理损坏提示。

## 4.5 正常收书与后台判断

无论是否质询，持书点击柜台偏左的归还托盘才代表接受并结束；可以不检查直接收书。托盘不自动检测或拒绝损坏书，不显示正确答案。无损坏书没有热点，不能凭空进入索赔。顾客感谢后复用转身、入口、门铃及离场流程，不需要扫码。

A 对划痕索赔后收书正确，放过或漏查后收书错误；B 直接收书正确。每处决定记录在 damageDecisions，最终操作统一为 accept。最终检查所有当前损坏：旧损坏收费记 charged_existing_damage，新增损坏未收费（包括没点到）记 missed_new_damage。对错和原因只留在数据层，不向正常玩家反馈。

状态由 Transaction 管理：RETURN_BOOK_PLACED → RETURN_BOOK_HELD ↔ RETURN_BOOK_INSPECT → RETURN_DAMAGE_SELECTED → RETURN_DAMAGE_DIALOGUE → RETURN_DECISION → RETURN_BOOK_HELD。主动收书后 RETURN_ACCEPTED → 回应/离场 → RETURN_COMPLETE，只保存一次。

记录包含 transactionType、customerId、bookId、bookInstanceId（记忆模式）、actualDamagePresent、actualDamageResponsibility、selectedDamageId、damageDecisions、finalDecision、isCorrect、reason、errors、timestamp。existingDamageBeforeLoan 保存既有损坏 ID，不提供玩家历史对比页面。开发模式可查看诊断；正常模式不暴露 window.library。

## 4.6 跨交易书况记忆测试（已实现）

入口 `?mode=memory`，或开始页「记忆循环测试」。依序为林舟借《远方的灯塔》→ 安静 5 秒 → 周宁借《城市里的雨》→ 安静 10 秒 → 林舟归还原书。两人借阅证正常，人物沿用同一 Profile；林舟回访复用原模型，不更换头发或衣服。业务间保留环境声和有限转头，不黑屏、不加载、不连续弹提示。

BookDefinition 保存书名及外观，BookInstance 保存副本 ID、损坏、状态与持有人。灯塔书为 book_lighthouse_001，初始封面右下 fold_corner_01；借出保存损坏基线与持有人。归还前脚本加入第三页 coffee_stain_01 一次，原折角保留，重新绘制同一 Mesh 的表面。拒借的副本不会生成虚假的归还。归还完成后状态 IN_LIBRARY、持有人清空，折角和污渍持续存在。当前仅会话持久化，刷新重置测试。

折角质询：「这里为什么折了？」→「这个吗？」→ 停顿 →「我借的时候就已经这样了。」；污渍质询：「这一页上的污渍是怎么回事？」→「啊……」→ 停顿 →「喝东西的时候不小心碰到了。」。这些是角色台词，不增加系统比对。玩家可按任意顺序指出两处，也可漏查或都不查。

正确路线为折角不追究、污渍要求赔偿，最后放入托盘。旧损坏没有被指出也不会自动产生罚款；漏查新增损坏仍算错误。最终判断汇总逐处决定，错误留待未来结算。没有历史、借出截图、OLD/NEW 标签、损坏计数或漏查提醒。DEV 可查看实体、来源、持有人、序列位置和决定；正常界面不可见。

# 5. 阅读过场 / 时间推进

白天工作结束或需要推进时间时，玩家可以阅读自己桌面上的书。

这一流程**不另做一套操作**，继续复用书籍的统一交互。

1. 点击桌面上的书。
2. 书进入右手持有。
3. 按 **R** 进入中央查看。
4. 使用滚轮翻页。
5. 阅读若干页 / 完成本次阅读。
6. 书合上。
7. 时间推进，进入下一时段或下一天。

这里的重点是氛围与节奏，而不是增加新的按键或阅读 UI。

# 6. 整理书架 / 收书流程

这个阶段与柜台最大的区别是：

**玩家可以自由行走。**

## 6.1 拾取散落书籍

玩家看到地上、桌面或其他位置的书：

- 左键点击。
- 书进入右手持有位置。

如果仅凭封面 / 书脊无法判断分类：

- 按 **R** 检视。
- 旋转、看书脊、翻页。
- 判断它可能属于哪一类。
- 再按 **R** 退出。

## 6.2 放回书架

玩家拿着书走到书架前：

- 点击书架上的具体位置。
- 手中的书就被放置到该位置。

不是拖拽，而是：

**持有书 → 点击目标位置 → 放置。**

## 6.3 整个书架可交互

- 书架上的书都可以重新拾取。
- 玩家可以把已经放进去的书再拿出来。
- 玩家可以重新整理位置。

## 6.4 允许放错

系统**不阻止错误分类**。

玩家把书放到错误书架：

- 仍然正常放进去。
- 不弹红字。
- 不发错误音。
- 不立即显示正确 / 错误。

玩家可以之后自己发现问题，再重新拿出来移动。

### 反馈延后

整理书架的正确性只在最后结算阶段反馈。

因此整理过程中保持安静，不做即时“游戏判题式”反馈。

# 8. 设计原则总结

这套交互的核心不是让每种工作都有一套不同按键，而是让玩家形成稳定的身体记忆：

**看到东西 → 点击拿起 → 右手持有 → R 仔细看 → 再 R 回到手中 → 点击环境中的目标使用它。**

只有在“发现问题”时，才从物品交互自然进入对话。

借书、还书、阅读与整理书架都共享同一套基础操作语言，从而让后续增加更多工作内容时，不需要不断增加新的按键。

## 9. 柜台式对话镜头（2026-09-19 已实现）

- COUNTER_FREE：FOV 67°，小幅转头 ±5° / ±3°，等候与入场途中不锁定。
- DIALOGUE_FOCUS：约 0.7 秒聚焦面部附近，FOV 62°、向前 3cm；鼠标输入缩为 0.6 倍，偏移限制 ±2.5° / ±2°，保留第一人称观察。
- 开场：脸 → 手/书（0.5 秒轻低头 2°）→ 脸 → 手/证件；放完后停顿，0.5 秒回到普通控制。
- 借出：扫码声音发生时不主动改镜头；等待 0.25 秒后聚焦顾客，将「谢谢」「晚上辛苦了」分开。
- 拒借：留在暂存盘方向 0.3 秒，再用 0.8 秒回看人物；保留「这样啊……」「那算了」之间的沉默。
- 顾客离场前解除聚焦，不追随离开的顾客；证件提问与递还复用轻聚焦。
- OBJECT_INSPECT：专供中央书籍检视，维持 R/拖动/滚轮操作；侧持证件仍可观察顾客，不改回中央检视。


## 10. 闭馆与整理（2026-09-20 已实现）

Game Phase 独立于交易状态和 Camera Mode：DAY_COUNTER → CLOSING_READING → CLOSING_TRANSITION → NIGHT_FREE_ROAM → NIGHT_SHELVING → NIGHT_SHELVING_COMPLETE。最后顾客离开后先等待 2.5 秒，再开启私人书；夜間准备完毕时因存在待整理书，FREE_ROAM 自然进入 SHELVING。

《夜航》不参与馆藏、损坏或顾客交易。新页连续停留 2 秒推进一次时间，21:47 → 21:51 → 21:55 → 21:58 → 22:00；重复页、菜单和拖动期间不推进。到点不抢控制，玩家 R 退出后合书归桌；「好了，下班了」台词结束 0.7 秒后才 CLOSED、调暗部分灯 20%、站起 18cm/后移 8cm。

FREE_LOOK 下点击画面取得鼠标锁定，WASD 以 1.45m/s 行走并与固定家具滑动碰撞。中心射线命中目标，手部高度到目标距离不超过 1.5m、视线不超过 2.4m；家具阻挡命中。R 进入 OBJECT_INSPECT 期间暂停移动/转头，锁定鼠标的 movementX/Y 在按住左键时只旋转书；滚轮翻页，R 返回右手，鼠标锁定不断开。Esc/失去锁定清除移动与拖动状态。

四个带实体标签的分类架各 6 槽，共 13 本原架书和 6 本散落书（2026-09-21 新增《夜空图鉴》到科普架原空槽）。左键实际命中哪个槽，就对齐滑入哪个槽，0.38 秒完成；占用槽不响应，类别不影响放置。所有 19 本书均能重新拿出。六本任务书全部入槽且空手后显示约 1.4 秒「书都收起来了」，清场开始前再拿书撤销完成。后台最终布局统计全部可操作书（包括挪错的原架书），只在 DEV 显示判断；没有即时分类反馈、工资或下一天。

## 11. 闭馆清场（2026-09-20 已实现）

NIGHT_SHELVING_COMPLETE 保持 2 秒 → NIGHT_CLEARING，显示「还有人没走吗……」1.5 秒。三位普通读者在整理阶段已可见但不能提醒。进入清场后空手、1.8m 内中心射线命中人物才显示「提醒闭馆」，左键或手机「提醒」触发；处理顺序任意，不能重复提醒，不显示人数、箭头或奖励。

每位读者独立沿 LINGERING → DIALOGUE → PREPARING_TO_LEAVE → LEAVING → EXITED 推进，不创建借还交易。站立对话镜头 0.55 秒聚焦面部，FOV 67° → 63.5°、前移 1.5cm，保留约 ±2°/±1.5° 转头，冻结行走。老人缓慢回应、青年停顿稍长、小孩靠近且视线可达时只起身一次。起身避开玩家站位，准备离场后用 0.45 秒恢复 FREE_LOOK，镜头不追随。

读者沿预设空地路径避开家具和玩家，在门前依次通行。入口 lockedFromOutside 保持 true、canExitFromInside 为 true；门打开时室内雨声层由 .12 微调到 .15，门关后恢复，最后读者走出侧边视野才记 EXITED。三人全部 EXITED 后留白 1.5 秒，「馆里已经没人了。」显示 1.5 秒，进入 NIGHT_CLEARING_COMPLETE。仍可走动、R 检视和重排书，不倒退回整理阶段；随后进入第 12 节门外推荐事件。

直接入口 `?mode=clearing` 从整理完成后的状态开始。`?dev=1` 额外提供读者状态/提醒/离场/门锁的只读诊断；普通 UI 隐藏这些信息。对应需求：requirements/2026-09-20-night-clearing-flow.md。

## 12. 门外访客与推荐（2026-09-21 已实现）

NIGHT_CLEARING_COMPLETE 保持 1 秒 → NIGHT_RECOMMENDATION_WAIT 等待 5.5 秒 → 门外陈遥从侧边走近、敲门三下。期间自由行走，镜头不自动转向访客。门保持外锁内出且从不打开；室外路径与室内碰撞分离。

1.9m 内以中心准星瞄准访客，左键 / 手机「询问」进入 NIGHT_RECOMMENDATION_REQUEST。初次询问可持书，不提交。沿用站立聚焦：0.55 秒、FOV 63.5°、前移 1cm；暂停行走，保留小幅转头。请求为给妹妹找简单、图多的星空书，结束后恢复 FREE_LOOK 和 NIGHT_RECOMMENDATION_SEARCH。忘记需求可空手回来听一句简短重复，没有任务清单。

《夜空图鉴》是正常科普馆藏 BookInstance，初始位于 science_5；深蓝月亮封面、月相 / 北斗七星 / 行星三页插图和简短文字。全部 19 本实体书继续共用拾取 / R / 拖动 / 翻页 / 槽位放置；后台 recommendationTags 与 acceptableBookIds 不投射到玩家界面。手持和检视物使用独立前景深度绘制，近处家具不再切开书页，物件自身遮挡与损坏射线仍正常；归架恢复场景深度。

听过请求后，持书靠近并点击「推荐这本」才提交一次，进入 NIGHT_RECOMMENDATION_PRESENT。提交前自由换书；提交后不可重试。Controller 使用可接受实例 ID 列表，支持多个合适答案。结果记录 requestId、visitorId、recommendedBookId、acceptableBookIds、isCorrect、presentedAt、visitorExitedAt；不生成借阅、赔偿或奖励记录。

停顿 0.6 秒后访客给自然反馈，再解除镜头并点头、后退、沿门外路径离开。书一直由玩家持有。只有已提交、访客实际离场、推荐书位于某个 ShelfSlot 且玩家空手，才进入 NIGHT_RECOMMENDATION_COMPLETE；放错分类也允许，不即时判题，不再回到 NIGHT_SHELVING。完成不增加通知，保留自由走动；下一阶段未接入。

`?mode=recommendation` 直接从闭馆、整理和清场均已完成开始；`&dev=1` 额外显示访客状态、需求、标签、可接受书目、提交与归架数据。推荐结果与实体布局仅保留当前页面会话，刷新重置。对应需求：requirements/2026-09-21-night-recommendation-flow.md。
