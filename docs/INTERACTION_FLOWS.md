# Nightfall Library 交互流程设计

> 本文记录 2026-09-18 已确认的交互方案。重点是统一玩家的操作语言，减少按键数量，并明确借书、还书、阅读过场与整理书架四类流程。

## 1. 全局交互原则

### 1.1 核心操作语言

- **鼠标移动**：控制视线。
- **鼠标左键单击**：拾取物品 / 使用手中物品 / 点击可交互信息。
- **R**：进入或退出“书籍检视模式”。
- **检视模式中按住左键拖动**：旋转书籍，可从各角度查看。
- **鼠标滚轮**：翻页 / 合理范围内前后翻看。
- 尽量不引入额外功能键，不使用拖拽完成“拿起—放置”这类基础工作动作。

### 1.2 两种空间状态

#### 柜台工作状态
用于借书与还书。

- 玩家坐在柜台后。
- 不能自由行走。
- 鼠标只允许小幅转头，保持固定构图与夜班柜台氛围。
- 物品拾取后默认进入**右手持有位置**，而不是直接占满画面中央。

#### 整理书架状态
用于夜间/闭馆后的收书与归类。

- 玩家可以自由行走。
- 仍沿用相同的“点击拾取 → 右手持有 → R 检视 → 点击目标位置放置”的交互语言。

---

# 2. 书籍的统一状态

一本书在游戏中主要有以下状态：

1. **场景中**
2. **右手持有**
3. **中央检视**
4. **用于场景交互**
5. **被放置 / 被扫码 / 被退回**

## 2.1 拾取

玩家左键点击桌面、地面或书架上的书：

- 书从原位置离开。
- 移动到画面右侧的右手持有位置。
- 保持能看到封面 / 书脊的一部分，书脊应尽量能阅读标题。
- 此时玩家仍可正常看向顾客或环境。

## 2.2 进入检视

手中持书时按 **R**：

- 书从右侧移动到画面中央。
- 进入书籍检视模式。
- 玩家不再执行普通场景点击。

检视模式中：

- **按住左键拖动**：旋转书籍。
- **滚轮**：翻页。
- 可查看封面、封底、书脊、页面及预设的损坏位置。

再次按 **R**：

- 退出检视模式。
- 书回到右手持有位置。
- 玩家恢复对环境的普通交互。

# 3. 借书流程

## 3.1 顾客入场

顾客走到柜台前，将：

- 读者证
- 要借的书

放到桌面。

玩家保持固定柜台视角。

## 3.2 查看读者证

玩家左键点击读者证：

- 读者证被拾取。
- 直接显示在画面右侧、足够清晰可读的位置。
- **读者证不需要再按 R 才能查看。**
- 玩家可以一边看证件，一边移动视线观察顾客本人。

### 证件上的可交互信息

证件不需要被拆成大量区域，只保留少量关键热点，例如：

- 照片
- 姓名
- 日期 / 有效信息

这些热点是“提出疑问”的入口，不是小游戏式找茬。

### 对证件提出疑问

如果玩家认为某一项有问题：

1. 直接点击该信息区域。
2. 立即触发与该信息相关的提问 / 对话。
3. **不需要再点击顾客才能开始提问。**

例如：

- 点击照片 → 询问“这张照片和你现在看起来不太一样。”
- 点击日期 → 询问证件日期 / 有效性相关问题。

顾客回答后，玩家仍保留证件。

### 结束证件阶段

玩家持有证件时点击顾客：

弹出一个很轻的两项选择：

- **还给你**
- **我还有问题**

选择“还给你”：

- 证件递还顾客。
- 证件核验阶段结束。

选择“我还有问题”：

- 继续保留证件。
- 玩家可以继续点击证件信息提出问题。

这样避免“把证件放回桌面”这一不自然动作。

## 3.3 检查借阅书籍

玩家点击桌上的书：

- 拾取到右手位置。

如需仔细检查：

1. 按 **R** 进入检视。
2. 按住左键拖动旋转。
3. 滚轮翻页。
4. 再按 **R** 退出检视。

## 3.4 借出 / 拒借

书处于右手持有状态时：

### 借出

玩家点击右侧扫码机 / 借出设备：

- 手中的书移动到扫码区域。
- “滴”一声。
- 借出成功。

### 拒绝借出

玩家点击待处理书篮 / 拒借区：

- 书被放入待处理区域。
- 本次借阅不成立。

系统不替玩家自动判断证件是否正确；玩家的行为本身就是最终决定。

# 4. 还书流程

还书比借书更强调“发现书籍问题 → 与顾客交涉 → 决定是否接收”。

## 4.1 顾客提交书籍

顾客来到柜台，将要归还的书放到桌面。

玩家点击书：

- 书进入右手持有状态。

按 **R**：

- 进入中央检视。

玩家可以：

- 旋转书籍。
- 翻页。
- 查看封面、书脊、页面。
- 寻找划痕、破损、污渍、缺页等异常。

## 4.2 破损如何实现

破损**不需要做复杂的 3D 建模**。

例如封面划痕可以由：

- 贴图 / decal / 局部纹理表现视觉效果。
- 一个与视觉位置对应的透明交互热点负责点击检测。

因此“看得见的划痕”和“可点击区域”可以分离实现，不需要给每一道划痕增加实体几何。

### 点击与旋转冲突的处理

在检视模式中：

- **短按 / 轻点左键**：点击损坏热点。
- **按住并发生拖动**：旋转书籍。

实现时应设置最小拖动距离 / 持续时间阈值，从而区分 click 与 drag。

## 4.3 点击损坏后的镜头与对话

当玩家点击一个确认存在的损坏热点，例如封面划痕：

1. 记录玩家此时书籍的旋转姿态。
2. 书从中央检视位置移动到画面右侧。
3. **保持刚才检查时的姿态，不自动转正。**
4. 视线重新构图，使玩家能够同时看到：
   - 顾客
   - 有问题的书 / 破损位置
5. 自动进入该破损对应的对话。

例如：

“这里的封面为什么有一道划痕？”

顾客进行解释。

## 4.4 赔偿决策就在对话中完成

顾客解释之后，**不要退出对话再做额外操作**。

直接在当前对话中给玩家决策，例如：

- 要求赔偿
- 不追究 / 接受解释
- 拒绝接收本次还书

如果玩家要求赔偿：

- 顾客可能同意。
- 也可能拒绝。

### 顾客同意赔偿

- 对话完成赔偿处理。
- 书仍可继续进行归还。
- 对话结束后恢复到原先的书籍检查 / 持有流程。

### 顾客拒绝赔偿，玩家拒绝接收

- 本次还书失败。
- 书直接判定为退回给顾客。
- **不要求玩家再额外点击顾客完成“递回”动作。**
- 这一结果直接由对话中的决策完成。

## 4.5 对话结束后的状态恢复

如果本次还书仍继续：

- 结束对话后恢复到玩家此前的书籍查看状态。
- 保留刚才的书籍姿态与上下文。
- 玩家可以继续检查其他位置。

检查完成后：

1. 按 **R** 退出检视。
2. 书回到右手持有。
3. 点击还书扫码区域。
4. 扫码提示音响起。
5. 完成归还。

# 5. 阅读过场 / 时间推进

白天工作结束或需要推进时间时，玩家可以阅读自己桌面上的书。

这一流程**不另做一套操作**，继续复用书籍的统一交互。

1. 点击桌面上的书。
2. 书进入右手持有。
3. 按 **R** 进入中央查看。
4. 使用滚轮翻页。
5. 阅读若干页 / 完成本次阅读。
6. 书合上。
7. 时间推进，进入下一时段或下一天。

这里的重点是氛围与节奏，而不是增加新的按键或阅读 UI。

---

# 6. 整理书架 / 收书流程

这个阶段与柜台最大的区别是：

**玩家可以自由行走。**

## 6.1 拾取散落书籍

玩家看到地上、桌面或其他位置的书：

- 左键点击。
- 书进入右手持有位置。

如果仅凭封面 / 书脊无法判断分类：

- 按 **R** 检视。
- 旋转、看书脊、翻页。
- 判断它可能属于哪一类。
- 再按 **R** 退出。

## 6.2 放回书架

玩家拿着书走到书架前：

- 点击书架上的具体位置。
- 手中的书就被放置到该位置。

不是拖拽，而是：

**持有书 → 点击目标位置 → 放置。**

## 6.3 整个书架可交互

- 书架上的书都可以重新拾取。
- 玩家可以把已经放进去的书再拿出来。
- 玩家可以重新整理位置。

## 6.4 允许放错

系统**不阻止错误分类**。

玩家把书放到错误书架：

- 仍然正常放进去。
- 不弹红字。
- 不发错误音。
- 不立即显示正确 / 错误。

玩家可以之后自己发现问题，再重新拿出来移动。

### 反馈延后

整理书架的正确性只在最后结算阶段反馈。

因此整理过程中保持安静，不做即时“游戏判题式”反馈。

| 普通场景 | 鼠标移动 | 看向环境 / 小幅转头 |
| 普通场景 | 左键点击物品 | 拾取 |
| 右手持书 | R | 进入书籍检视 |
| 中央检视 | R | 退出检视 |

| 持有读者证 | 点击顾客 | “还给你 / 我还有问题” |

# 8. 设计原则总结

这套交互的核心不是让每种工作都有一套不同按键，而是让玩家形成稳定的身体记忆：

**看到东西 → 点击拿起 → 右手持有 → R 仔细看 → 再 R 回到手中 → 点击环境中的目标使用它。**

只有在“发现问题”时，才从物品交互自然进入对话。

借书、还书、阅读与整理书架都共享同一套基础操作语言，从而让后续增加更多工作内容时，不需要不断增加新的按键。
